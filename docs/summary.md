# Submission summary

What worked: the pack runs offline with one command (`python3 run_tests.py`: PASS 38 / FAIL 0 / SKIP 0), the eight connector-native cases each produce their exact expected decision, and the four safety invariants are tested by mutating every case (an injection in each field, deleted IDs and times, reordered events, planted canaries), with the same `check()` also catching an always-ACCEPT, an always-QUARANTINE and an always-crashing policy and a wrong AIR-06 state.
What failed: the first green run was not enough evidence, because two independent reviews then found real gaps: a stale Jira "Resolved" could win when the reopen arrived as a non-status edit, distinct record updates could be deduplicated, an out-of-range date crashed into `POLICY_ERROR`, and roughly half of the test reviewer's deliberately broken policies passed the whole suite; all of these are now fixed and covered by tests.
What I deliberately did not build: mutation-testing tooling, an eval scorecard, semantic or keyword correlation, large injection corpora, live connectors, real signature verification, any model, and any third-party dependency.
Known limits that remain: detection is pattern-based and advisory (a Cyrillic look-alike injection is missed, though it is shown to change nothing), names in free text and personal data in undeclared fields are not redacted, and correlation across connectors is a time window that can only ever suggest a link.
With authorised access I would calibrate the fixtures and the observed-versus-asserted table against real, redacted connector payloads and adapter provenance, then run the production agent in place of `decide()` over these fixtures and mutations to track violation rates per invariant on every release.
